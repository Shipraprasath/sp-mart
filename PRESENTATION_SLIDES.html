Motivation & Challenges

Problem Statement in Electronics Retail

  • ✕
    AI Hallucination Gap: Generic chat bots invent non-existent specifications and recommend out-of-stock electronics because they lack relational inventory grounding.
  • ✕
    Security & Privilege Bleed: Monolithic systems frequently fail to enforce strict boundaries between merchant fulfillment and administrative governance.
  • ✕
    Friction in Mobile Access: Native apps require high Play Store review friction, while traditional mobile websites lack offline caching and installability.
Architecture Overview

The SP MART Architectural Solution

1. Catalog-Grounded AI Assistant

Extracts budget numbers (e.g. ₹30,000, 75k) and target devices, querying active JPA database records directly to ensure 100% verified responses.

2. Multi-Role RBAC Governance

Strict vertical privilege separation across Customers (ROLE_CUSTOMER), Approved Merchants (ROLE_SELLER), and Admins (ROLE_ADMIN).

3. Progressive Web App (PWA)

Provides a native Android and iOS mobile app install experience directly from the web browser via Service Worker and Web App Manifest.

4. Robust Enterprise Backend

Layered architecture backed by 31 automated tests, BCrypt cryptographic password hashing, and cookie-based CSRF defense.

Information Security

Cybersecurity & Defense-in-Depth

Cryptographic Storage

Passwords hashed using BCrypt (strength factor 12) with per-user salt. Immune to rainbow tables.

CSRF Token Repository

Configured with CookieCsrfTokenRepository and eager token pre-resolution to prevent response buffer commit crashes.

SQL Injection Prevention

Zero dynamic concatenation. 100% strongly-typed parameter binding via Spring Data JPA and Hibernate ORM.

Session Fixation Defense

Spring Security automatically issues fresh session IDs upon authentication, preventing session hijacking.
